# リファクタリング・クラス設計のルール
## クラスの規模・構造

クラスは 原則 300行以内 に収める（長くなったら責務分離を検討）

単一責任の原則（SRP） を守る

クラス名は 責務が一目で分かる名前 にする（例: PlayerMovementController）

MonoBehaviour を継承するクラスは UI / ゲームロジック / 入力処理 などの役割を明確化

## メソッドのルール

1メソッドは 40行以内 を目安

メソッドは 1つの目的・操作 に限定する

ネスト（if, for, while）は 3段まで。それ以上は早期 return やメソッド分割

メソッド名は 「何をするか」 が明確に伝わる動詞で（例: LoadUserData(), ShowWarning()）

## ファイル構造と依存

1ファイル1クラスを基本とする（struct, enum, interface は同居可）

UIとロジックは別クラスに分離

特定の機能に関するスクリプト群は フォルダ単位でまとめる

## 命名・コメント

命名規則は統一

自明なコードにコメントは不要、処理の意図 に対してコメントを書く

メソッドはコメントは極力入れること

## その他

マジックナンバー禁止 → 定数化 (const or readonly)

Update()内の処理は必要最小限に限定、重処理はコルーチンや遅延実行へ

リファクタリング時は 既存の挙動を壊さない手動チェック を必ず行う

再利用可能な処理は UtilityクラスやExtensionメソッド に切り出す
